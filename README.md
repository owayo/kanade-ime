Kanade は Windows と macOS で使える日本語入力 IME です。「くるまにのります」と「ざっしにのります」のように同じ読みでも表記が変わるとき、同梱の言語モデル **Tsumugi（つむぎ）** が文脈をもとに候補を選びます。自分で選んで確定した言葉や訂正も、次回の変換に反映します。

現在は開発版です。通常変換と学習は実装していますが、配布版としてのネイティブ検証は続いています。[実装状況と残作業](docs/status.md)を確認してください。

## 機能

| 機能 | 動作 |
|---|---|
| かな漢字変換 | Mozcで変換し、OSの候補ウインドウで表示 |
| 選択・訂正の学習 | 明示的に選んで確定した候補や訂正を次の変換へ反映 |
| 学習の除外 | 全アプリを既定の対象とし、設定からアプリを除外 |
| 追加候補 | 絵文字、計算した日付、承認済みプロジェクトの識別子。日付候補が有効なときは「にせんきゅうねんのはる」を「2009年の春」に変換 |
| ローカルAI | Tsumugi が読みと文脈から Mozc の候補を比較し、最初の変換に反映 |
| 設定画面 | ユーザー辞書、学習記録、モデル、プロジェクト辞書を管理 |

入力・キー・文書の抜粋を診断ログに記録しません。パスワード入力は変換エンジンを経由せず、プライベート入力や入力先を判別できない場合は永続学習を無効にします。通常の入力内容をネットワークサービスへ送信しません。

### 同梱の言語モデル Tsumugi

Tsumugi は、かな漢字変換の候補に点数を付けるために学習した言語モデルです。Space を押すと、まず Mozc の候補が表示されます。ローカル AI を有効にすると、Tsumugi が読みとキャレット直前の最大40文字を手掛かりに、端末の CPU で候補を比較します。空の入力欄でも入力中の文の前半を使えるため、「くるまにのります」は「車に乗ります」、「ざっしにのります」は「雑誌に載ります」と一度の変換で書き分けられます。

Windows 用 EXE と Mac 用 DMG は、どちらも **Tsumugi 26.11.105**（約2,806万パラメータ、GGUF ファイル 66.5 MB）を同梱しています。同梱はプレビュー版 26.11.117-preview.6 からで、それより前の版に入っているのは 26.11.102 です。Tsumugi はインストーラーに同梱して配布します。26.11.105 からは、モデルだけの Release を作っていません。利用するには、Kanade の設定でモデルの利用条件と端末内処理に同意し、同梱モデルを取り込んでローカル AI を有効にします。[モデルの仕様](docs/llm.md#tsumugi-model)・[学習に使った文章の出典](docs/third-party.md#tsumugi-training-data)・[採点の仕組み](docs/llm.md)

**Tsumugi の有効・無効で、一発変換はどれだけ変わるか**

Windows 版 Kanade で Tsumugi の設定を切り替え、各版に同じ6,600件の読みと文脈を入力しました。Space を1回押し、候補の更新後に表示された全文が原文またはあらかじめ認めた表記と一致すれば正解です。6,600件のうち1,320件は開発時の調整にも使っています。

| Windows 版 Kanade | Tsumugi | 無効の正解件数 | 無効時の正解率 | 有効の正解件数 | 有効時の正解率 |
|---|---|---:|---:|---:|---:|
| 配布版 26.11.116-preview.4 | 26.11.102 | 3,542件 | 53.67% | 3,929件 | 59.53% |
| 開発版 `b0461e2` | 26.11.102 | 3,542件 | 53.67% | 4,108件 | 62.24% |
| 開発版 `5c19c16` | 26.11.105（26.11.117-preview.6 が同梱） | 3,542件 | 53.67% | 4,637件 | 70.26% |
| 配布版 26.11.117-preview.6 | 26.11.105 | 3,542件 | 53.67% | 4,620件 | 70.00% |
| 開発版 `4f925ff` | 26.11.105 | 3,542件 | 53.67% | 4,681件 | 70.92% |

開発版は、句読点で区切った全ての節と長い文の前半も採点し、数字の書き方と西暦の年を文脈に合わせます。Tsumugi 26.11.102 のままでも、有効にすると668件が新たに正解し、無効時に正解だった102件が不正解になりました。差し引き **566件増、6,600件に対して8.58ポイントの上昇**です。調整に使っていない5,280件では、2,824件から3,282件に増えました。前回の開発版 `399bbed` は有効時に3,947件でした。配布版 26.11.116-preview.4 では477件が正解に変わり、90件の正解を失い、差し引き387件増でした。[測定した開発版](https://github.com/owayo/kanade-ime/commit/b0461e28737b259c9c3562bf5d7c9d326f4c7556)・[配布版](https://github.com/owayo/kanade-ime/releases/tag/v26.11.116-preview.4)

Tsumugi 26.11.105 は、日本語版 Wikipedia の全記事から、測定に使う記事と文を除いて学習した重みです。開発版 `5c19c16` のカタログにこの重みを登録して測ると、有効時に1,187件が新たに正解し、92件の正解を失いました。差し引き **1,095件増、16.59ポイントの上昇**です。調整に使っていない5,280件では、2,824件から3,715件（70.36%）に増えました。この重みはプレビュー版 26.11.117-preview.6 から同梱しています。[測定した開発版](https://github.com/owayo/kanade-ime/commit/5c19c160e24979e537d4d7bafcbea74cb2069a32)

配布版 26.11.117-preview.6 は、Windows にインストールして同じ6,600件を測りました。インストールされたファイルは、Release の `SHA256SUMS` と一致するインストーラーの中身と同じです。学習履歴のない状態で、Tsumugi の設定だけを切り替えました。無効時は3,542件で、開発版 `5c19c16` と入力ごとの正誤がすべて一致しました。有効時は4,620件（70.00%）です。1,170件が新たに正解し、92件の正解を失い、差し引き **1,078件増、16.33ポイントの上昇**でした。調整に使っていない5,280件では、2,824件から3,703件（70.13%）に増えました。開発版 `5c19c16` より17件少なく、新たに正解した入力はありません。配布用にビルドした推論プログラムは、測定した PC でビルドした開発版より1回の採点が約4割遅くなっています。Kanade は、句読点で区切った2つ目以降の節と、長い文の残りの部分の採点を、Space から350ミリ秒以内にだけ始めます。17件はどれも、更新の終了までに350ミリ秒を超えた入力でした。[プレビュー版 26.11.117-preview.6](https://github.com/owayo/kanade-ime/releases/tag/v26.11.117-preview.6)・[配布版の採点が遅い件](https://github.com/owayo/kanade-ime/issues/37)

開発版 `4f925ff` は、数の読みが別々の語に変換されたときに、1つの数として読み直した候補も採点します。たとえば「大会には」に続く「ひゃくにじゅうにんがさんかした」は、「百に住人が参加した」ではなく「百二十人が参加した」になります。Tsumugi 26.11.105 を有効にしたときの正解は、開発版 `5c19c16` の4,637件から4,681件に増えました。44件が新たに正解し、失った正解はありません。無効時と比べると、1,231件が新たに正解し、92件の正解を失い、差し引き **1,139件増、17.26ポイントの上昇**です。調整に使っていない5,280件では、2,824件から3,749件（71.00%）に増えました。[測定した開発版](https://github.com/owayo/kanade-ime/commit/4f925ff84b5e5f17c4ae3e523263d8155aede25d)

最初の候補表示から更新終了までの時間は、開発版の測定では、26.11.102 で半数が99ミリ秒以内、95%が175ミリ秒以内でした。26.11.105 では104ミリ秒以内と241ミリ秒以内です。数の読み直しを加えた開発版 `4f925ff` では、107ミリ秒以内と236ミリ秒以内でした。インストールした配布版 26.11.117-preview.6 では、165ミリ秒以内と363ミリ秒以内でした。別のモデル単体テストでは、あらかじめ候補を与えた同音語85問のうち、26.11.102 は78問、26.11.105 は82問で期待した表記を1位に選びました。[モデル単体のテスト条件](docs/llm.md#tsumugi-model)

## 動作環境

配布対象はApple SiliconのMacとWindows x64です。Windowsの32bitアプリには同梱の入力DLLを使います。Linux、Intel Mac、Windows ARM64の配布物は作りません。

ソースからのビルドには、mise、GitとOSの開発ツールが必要です。MacではXcode、Windowsでは対応するMSVC SDKとCMake、LLVMのclang-cl、Ninjaを用意します。推論ワーカーのllama.cppは、入っているVisual Studioの版によらずclang-clでビルドします（[理由と測定](docs/llm.md#building-the-worker-on-windows)）。Rust、Bazelisk、プロジェクト解析器の版はリポジトリで固定します。

## インストール

<!-- standard:install:start -->
### GitHub Releases から

プレビュー版を試す場合は、タグに `-preview.` が付いたリリースを開きます。Windows x64 の EXE は未署名、Apple Silicon Mac の DMG は一時署名・未公証です。どちらも Tsumugi を1つ同梱しています。インストーラーと同じリリースの `SHA256SUMS` でファイルを照合できます。[プレビュー版の一覧](https://github.com/owayo/kanade-ime/releases?q=preview)・[正式版](https://github.com/owayo/kanade-ime/releases/latest)

| プラットフォーム | ファイル |
|---|---|
| macOS (Apple Silicon) | `kanade-ime-aarch64-apple-darwin.dmg` |
| Windows (x86_64) | `kanade-ime-x86_64-pc-windows-msvc.exe` |

### ソースから

[mise](https://mise.jdx.dev/) が必要です (Rust のツールチェーンは `mise.toml` で固定しています)。

```bash
git clone https://github.com/owayo/kanade-ime.git
cd kanade-ime
make install
```

`make install` は `INSTALL_DIR` にアプリを入れます (既定の場所は `Makefile` にあります)。場所を変えるときは `INSTALL_DIR` を指定します。
<!-- standard:install:end -->

Windows のセットアップ EXE と macOS の DMG は Tsumugi を同梱しています。Windows では「半角／全角」でかな入力と半角英数を切り替えられます。ビルド済みのセットアップがあるチェックアウトで `install.bat` を実行できます。配布EXEをバッチの隣に置いても実行できます。

配布物が公開されるまではソースから開発用のインストールをしてください。`make install`はmacOS向けで、既存のコード署名用証明書が必要です。MacではDMG内のGUIインストーラー、WindowsではEXEセットアップを使います。公開後の導入手順と署名の確認は[配布とインストール](docs/distribution.md)にあります。

## 使い方

入力ソースにKanadeを追加し、本文の入力欄で選択してください。Macではかなキーで日本語入力へ戻り、英数キーでASCII入力に切り替えます。

| 操作 | 動作 |
|---|---|
| 半角／全角（Windows） | キャレットのそばに「A 半角英数」または「あ ひらがな」を約1秒表示 |
| タスクバーの「あ」／「A」（Windows） | 左クリックでかな入力と半角英数を切り替え。右クリックのメニューから設定画面を表示 |
| かなを入力してSpace | 変換候補を表示 |
| 外来語の読みを入力してSpace | 「まんでー」から `Monday`、「こーひー」から `coffee` を選択 |
| 候補の数字、上下キー、クリック | 表示中の候補を選択 |
| Enter | 選択した候補を確定 |
| F6〜F10 | ひらがな・カタカナ・英字などの文字種を切り替え |
| 入力メニューの「Kanade の設定…」（Mac） | 設定画面を表示 |

候補欄の下部に「AI 評価中…」と出ている間も、通常どおり候補を選んで確定できます。Tsumugi の採点が終わると、候補の順序が同じでも「AI 評価済み」と表示します。「AI 評価できず」や「AI 時間切れ」が出たときは、そのまま通常候補を使えます。「AI は設定が必要」は、並べ替えを有効にしたままモデルを使えなくなっているときに出ます。設定の「ローカルAI」に理由と必要な操作が表示されます。

先頭以外の候補を明示的に選んで確定すると、同じ読みの次の変換で優先します。直近の選び直しを先頭にし、そのほかは選択回数で並べます。先頭をEnterでそのまま確定しても選択回数は増やしません。確定が失敗した選択やキャンセルは記録しません。

設定画面の「学習しないアプリ」から除外対象を追加します。一覧を確認して保存すると、そのアプリでの選択記録と個人候補の優先表示を止めます。除外をすべて解除すると、全アプリが再び対象になります。プライベート入力を識別できないアプリは除外してください。

「候補・訂正の記録」では学習記録を確認・削除できます。Mozcの変換学習と予測学習は個別に消去でき、未確定入力や反映待ちの編集がある間は消去を拒否します。操作は取り消せません。

追加候補と補助機能には、次の設定があります。

| 設定 | 対象 |
|---|---|
| 絵文字辞書 | 読みや短縮名に一致する絵文字 |
| 計算日付 | 「こんげつまつ」などから求めた日付 |
| プロジェクト辞書 | 明示的に承認したフォルダの識別子 |
| ローカルAI | 同梱の Tsumugi による候補の並べ替え |

プロジェクト辞書はフォルダと対象アプリを確認してから作成します。承認前には解析しません。更新に失敗した場合も既存の辞書を保持します。

ローカルAIは初期状態では無効です。モデルの配布元と利用条件を確認し、端末内での処理に同意してから取り込みます。ファイルと応答品質の検証を通過した後に有効にできます。使用するモデルはTsumugiに固定しています。Kanade を更新すると、並べ替えを有効にしていた場合は Kanade がモデルを検証し直します。同梱モデルが替わった版に更新したときは、取り込み直すまで並べ替えは働きません。手順は[操作ガイド](docs/usage.md)にあります。

CLIの操作例とログの場所は[操作ガイド](docs/usage.md)を参照してください。計算日付や絵文字、プロジェクト辞書の動作も説明しています。ユーザー辞書の編集は[辞書の管理](docs/dictionary-management.md)、モデルのビルドと検証は[ローカルAI](docs/llm.md)にまとめています。

## 設定

普段の変更は設定画面で行います。Macでは入力メニューから、Windowsではタスクバーの「あ」／「A」の右クリックメニューか、スタートメニューの「Kanade の設定」から開きます。モデルの同意とプロジェクトの承認は、対象を確認する操作を経て保存します。ライブ変換、自動の候補生成、モデルの自動取得は未提供です。

Macのデータは`~/Library/Application Support/kanade-ime`、Windowsのデータは`%LOCALAPPDATA%\kanade-ime`に保存します。開発や検証では`KANADE_DATA_DIR`でデータディレクトリを指定できます。既存の個人データを使わない検証には、別のディレクトリを指定してください。

署名済みアプリの管理には、同じアプリに同梱したCLIを使います。開発用に別途ビルドしたCLIからの管理要求は、接続先の認証で拒否される場合があります。

## 開発

<!-- standard:dev:start -->
[mise](https://mise.jdx.dev/) が必要です。ツールの版は `mise.toml` で固定しています。

```bash
make setup   # ツールチェーン (mise) と依存を取得する
make ci      # CI と同じ検査 (書き換えない)
```

| コマンド | 説明 |
|---|---|
| `make setup` | ツールチェーン (mise) と依存を取得する |
| `make build` | デバッグ版をビルドする |
| `make release` | リリース版をビルドする |
| `make bundle` | リリース版をアプリにまとめる |
| `make dev` | デバッグ版のアプリを起動する |
| `make run` | リリース版のアプリをインストールして起動する |
| `make test` | テストを実行する |
| `make lint` | clippy を警告ゼロで通す |
| `make fmt` | コードを整形する (書き換える) |
| `make fmt-check` | 整形済みかを確かめる (書き換えない) |
| `make check` | 整形と静的検査 (書き換えない) |
| `make ci` | CI と同じ検査 (書き換えない) |
| `make install` | リリース版のアプリを INSTALL_DIR に入れる |
| `make uninstall` | INSTALL_DIR からアプリを取り除く |
| `make clean` | ビルド成果物を消す |

`make` でターゲットの一覧を表示します。リリースは GitHub Actions で行います (**Actions → Release → Run workflow**)。
<!-- standard:dev:end -->

入力と候補表示はmacOSのInputMethodKitとWindowsのTSFで処理します。変換には別プロセスで動く無改造のMozc、設定画面にはGPUIを使います。

Cargoの通常のビルドではBazelを起動しません。Mozcワーカーは`make worker`で明示的にビルドします。`make contract`は実ワーカーの変換・確定・復旧を、`make project-contract`はプロジェクト辞書の索引と通知を検証します。

`make version`で版の整合性を確認し、`make bump-version`で日本時間の年月とカウンターに基づいて一括更新します。通常のビルドでは版を変更しません。
