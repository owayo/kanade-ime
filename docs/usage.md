# Kanadeの操作ガイド

無改造の Mozc を別プロセスで使う、日本語入力IMEの開発版です。macOS は InputMethodKit、Windows は TSF で入力と候補表示を処理します。GUIにはGPUIを使います。

通常変換、候補選択、確定、訂正学習、障害時のかなへの復旧を実装しています。配布版としての検証は終わっていません。[実装状況と残作業](status.md)を確認してください。

## ビルドと検証

Rust、Bazelisk、開発用の astro-sight は mise で固定しています。Bazel 本体も `USE_BAZEL_VERSION` で指定し、ワーカーのビルドではロックに記録した版を使います。Xcode または対応する MSVC SDK、Git、curl は OS 側で用意します。Cargo の通常ビルドから Bazel は起動しません。

```bash
git clone --recurse-submodules https://github.com/owayo/kanade-ime.git
cd kanade-ime
make setup
make check
make contract
make evaluate
```

`make` だけでターゲット一覧を表示します。各ツールは `mise exec --` 経由で実行するため、シェルで mise を有効にしていなくても固定した版を使います。`SYSTEM_TOOLS=1` を指定すると PATH 上のツールを使います。

`prepare` は固定した hasami のコミットと公開 API、サブモジュールの変更がないことを検証します。追加パッチは不要です。Mozc の作業ツリーは変更しません。`make check` は整形とClippyを、`make ci` はこれにワークスペースのテスト、MozcのSHAとprotoのハッシュ検証を加えて実行します。`make depup` で依存更新を実行できます。

`cargo xtask` は、起動したチェックアウトのファイルを読み書きし、その中で Cargo を実行します。チェックアウトの場所は `.cargo/config.toml` が渡すので、ターゲットディレクトリを別のチェックアウトと共有していても、場所が替われば xtask を作り直します。`cargo xtask check` の Clippy とテストは、チェックアウトごとに分けた `<ターゲットディレクトリ>/xtask-check/` の下に出力します。Cargo は更新日時で作り直すかを決めるため、別のチェックアウトと共有したりコピーしたりしたターゲットディレクトリで `cargo test` などを直接実行すると、そのチェックアウトでビルドした成果物を使うことがあります。

## バージョン

バージョンは `yy.m.counter` 形式です。日本時間の年月を使い、カウンターは100から始めます。同じ月の更新では1を加え、月が替わると100に戻ります。例は `26.11.100` → `26.11.101` → `26.12.100` です。Cargoの形式に合わせ、月をゼロ埋めしません。

```bash
make version                              # 現在の版と整合性を確認
make bump-version VERSION_FLAGS=--dry-run  # 次の版を表示するだけ
make bump-version                         # 採番し、関連ファイルを更新
```

`Cargo.toml` のワークスペース版を基準に、`Cargo.lock` とIME・設定アプリの両方のバージョンを更新します。失敗した更新は元に戻します。通常のビルドやインストールでは採番しないため、同じ版を再ビルドできます。`cargo xtask check` とバンドル作成時にも、バージョンの一致を確認します。

## 訂正学習の辞書

辞書の取得にはネットワークを使います。通常の入力、学習、文章の確認では、入力内容をネットワークへ送りません。

```bash
export KANADE_DATA_DIR="$HOME/Library/Application Support/kanade-ime"
mise run fetch-dictionary
KANADE_TEST_DICT="$KANADE_DATA_DIR/dict/ipadic.hsd" mise run learning-contract
```

取得する IPAdic とライセンス表示は `locks/dictionary.lock.toml` の SHA-256 で検証します。Windows の既定データディレクトリは `%LOCALAPPDATA%\kanade-ime` です。

学習は、既定ではすべてのアプリが対象です。設定で除外したアプリや、入力先を判別できない場合、プライベート入力ではMozcの永続学習を無効にします。パスワード欄では変換を迂回し、Kanadeの訂正記録は文書への反映をフロントエンドが確認してから保存します。

変換候補はMozcが作ります。hasamiは、修正後の語を解析して訂正学習の扱いを判定します。また、学習・プロジェクト辞書・絵文字検索で読みを正規化します。形態素解析と辞書の読み込みは、キー処理とは別のスレッドで行います。LLMが生成した候補の読みをhasamiで検証する機能は未実装です。

## macOS の開発用バンドル

バンドルの配置、再起動後のエンジン自動起動、入力ソースの追加と切り替えを確認済みです。利用者による実機試験では、日本語への変換もできています。候補のクリックやフォーカス移動などの検証は残っています。

```bash
make install
make verify-sign
make settings
```

`make install` はサブモジュールを準備し、Mozc ワーカーと署名付きバンドルを作ります。学習用辞書を取得した後、IME を登録し、LaunchAgent を設置して起動します。導入先は `~/Library/Input Methods/Kanade.app`、データは `~/Library/Application Support/kanade-ime` です。入力ソース一覧に表示されたら Kanade を追加して選択します。

既存の共有ローカル開発証明書を自動検出して署名します。別の証明書を使う場合は、名前または SHA-1 を指定してください。接続相手の認証に同じ署名証明書とカーネルの peer audit token を使うため、インストールには証明書が必要です。

```bash
make install CODESIGN_IDENTITY="your code signing identity"
```

`INSTALL_PATH` で配置先のディレクトリ、`KANADE_DATA_DIR` でデータの保存先を指定できます。`INSTALL_DICTIONARY=0` を指定すると辞書の取得を省きます。

`make status` は登録操作をせず、入力ソースの状態を表示します。表示するのは検出・有効の件数と、有効なモードID (`enabled_modes`)・現在の入力ソースIDです。ひらがなモードの ID は `com.apple.inputmethod.Japanese` です。一覧に出ない場合は、ログアウト・ログイン後に再確認してください。`ENABLE_INPUT_SOURCE=1` はインストール時に有効化も要求します。

Kanade が有効でも `enabled_modes` が空の場合は、以前のモード ID が登録に残っている可能性があります。システム設定の「キーボード → テキスト入力 → 編集」で Kanade を削除し、追加し直してください。古い登録を検出した場合、自動有効化は停止してこの手順を案内します。

更新時は未確定の入力を終えてください。Kanade選択中なら、インストーラが既存の英数キーボードへ切り替え、別プロセスで確認してから更新します。ほかの入力方式を使っている場合は切り替えません。既存のKanadeと設定アプリを通常終了させ、エンジンを再起動します。更新後は英数のままなので、かなキーか入力メニューでKanadeへ戻してください。更新中に利用者が切り替えた入力方式は保持します。

JIS 英数キーを押すと、未確定文字の文書への反映を確認してから、直前の英数キーボードへ切り替えます。利用者の実機試験で、物理キーによる切り替えを確認しました。文字の重複確定を防ぐテストも通っています。

かなキーは文字として入力せず、空白の混入を防ぎます。候補欄には候補と補足を左揃えで表示し、読みの列と下部の入力文字は表示しません。アプリと入力メニューのアイコンは `assets/icons` の画像からビルド時に生成します。

入力メニューと入力位置の切り替え表示にも、トレイと同じ画像を指定しています。更新後も古い「K」が残る場合は、入力ソースを選び直してください。入力位置の表示には別のキャッシュがあるため、残る場合はログアウト・ログイン後に確認してください。

Windows では「半角／全角」でかな入力と半角英数の直接入力を切り替えます。英語配列では Alt とバッククォートの同時押しも使えます。IME オン・オフ専用キーに対応します。切り替えた入力モードは、キャレットの近くに2秒間表示されます。直接入力中の英字・数字・記号・スペースは、そのままアプリに入ります。入力方式の一覧（Win+Space）とタスクバーの入力インジケーターに出るアイコンも、`assets/icons` の画像からビルド時に生成し、入力 DLL に入れます。

Windows のひらがなモードでは、エンジンにつながらない間に通常の入力欄で変換を始める文字を打つと、その文字を捨ててカーソルの近くに5秒間知らせます。接続が戻ったら、その文字を入力し直してください。不通が続く場合は、前の通知から10秒以上たった後、次に文字を捨てたときにもう一度知らせます。IME 独自の画面を許可しないアプリ（UILess）では通知を表示できません。

標準の Windows 編集欄など、アプリが入力欄の種類を指定しない欄でも変換できます。パスワード欄・PIN 欄、読み取り専用の文書や範囲、アプリが IME を無効にした欄では、接続状態にかかわらずキーをアプリに渡します。選択範囲の途中で属性が変わるとアプリが通知した場合や、取得した入力スコープから種類を読み出せない場合も同じです。アプリが属性の変化点を通知できないときは、選択範囲に対して返された値を使います。プライベート入力を指定した欄では、周辺の本文を読まず、学習を無効にして変換します。

Kanade を選んでいる間、タスクバーの入力インジケーターに、かな入力なら「あ」、半角英数なら「A」を表示します。左クリックで2つを切り替えます。右クリックするとメニューが開き、入力モードの選択と設定画面の表示ができます。

英単語の綴りを入力したいときは、かなで読みを入力し、Space で候補を開きます。「まんでー」なら `Monday`、「こーひー」なら `coffee`、「らいと」なら `light` や `right` を選べます。かな入力のまま英字キーで続けて `monday` や `google` と打った場合も、Space で `Monday` や `Google` を選べます。英字候補は同梱辞書から表示され、オフラインでも使えます。

未確定文字があるときは、F6〜F10で順に、ひらがな・全角カタカナ・半角カタカナ・全角英数・半角英数へ変換できます。Ctrl+U / I / O / P / Tも同じ操作です。確定後や修飾付きFキーはアプリへ渡します。Macのキーボード設定によってはfnキーとの同時押しが必要です。

`make bundle` は `artifacts/macos.noindex/Kanade.app` までを生成します。`cargo xtask bundle-macos --debug` で開発用ビルドも作れます。設定アプリは `Contents/Helpers/Settings.app`、エンジンは `Contents/MacOS/kanade-engine` に入ります。これはローカル導入用の手順です。Windows への導入は [配布とインストール](distribution.md) を参照してください。

バンドル外で開発する場合は、エンジンと設定画面の両方に `KANADE_ALLOW_UNSIGNED=1` を明示して起動できます。この例外は debug ビルドだけで有効です。

```bash
KANADE_ALLOW_UNSIGNED=1 mise run engine
# 別のターミナルで実行
KANADE_ALLOW_UNSIGNED=1 mise run ui
```

## 設定と記録の管理

各項目は設定画面から操作できます。CLI からも管理できます。

- 候補・訂正学習、句読点での確定、計算日付、絵文字辞書の切り替え
- 学習しないアプリの追加・除外解除
- 候補の文字サイズと、1 ページの候補数
- 候補の選択回数と訂正記録の確認・削除
- ユーザー辞書の単語登録・編集・削除、辞書の作成・名前変更・削除
- 訂正記録から内容を確認してユーザー辞書へ登録
- Mozc の学習消去
- 手動で取得したローカルAIモデルの導入・検証・削除と、候補の並べ替え

Windows では、タスクバーの「あ」または「A」を右クリックして「Kanade の設定…」を選びます。スタートメニューの「Kanade の設定」からも開けます。ストアアプリのように制限された環境で動くアプリに入力している間は、右クリックのメニューからは開けません。スタートメニューを使ってください。

macOS では、入力メニューの「Kanade の設定…」から開けます。ウインドウは、ポインタのあるディスプレイに出ます。起動済みなら既存のウインドウを使い、次のように表示し直します。

- 最小化していれば元に戻します。
- 別のディスプレイにあれば、ポインタのあるディスプレイへ移します。同じディスプレイにあれば位置を変えません。
- 別の Space にあれば、作業中の Space へ移します。

ウインドウの重なり順は通常のままです。ほかのアプリが「常に手前」にしているウインドウよりも前には出ません。`⌘W` で閉じ、`⌘M` でしまい、`⌘Q` で終了します。

`Tab`／`Shift+Tab`で操作対象を移動し、ボタンやスイッチは`Enter`／`Space`で操作できます。フォーカスのある項目は色が変わり、画面外にあれば自動でスクロールします。入力欄の`Enter`で保存は行いません。辞書への登録や変更は、内容を確認して保存ボタンで実行してください。

エンジンに接続できなくても画面を表示し、「更新」で取得をやり直せます。取得できるまでは設定を変更できません。

候補一覧から明示的に選んで確定した語は、次の変換で優先します。直近に選び直した候補を先頭にし、そのほかは選択回数で並べます。先頭の候補をEnterでそのまま確定しても、選択回数は増やしません。表示中の候補順は保ち、別の入力欄で進んだ学習は次の変換から反映します。確定が失敗した場合やキャンセルした選択は記録しません。

初期状態では、すべてのアプリで学習します。学習させたくないアプリは「学習しないアプリ」の「除外アプリを編集…」から追加してください。macOSでは「アプリを選択…」で追加でき、IDを直接入力する方法もあります。一覧を確認して「この除外設定で保存」を押します。除外をすべて解除すると、全アプリが再び対象になります。変更後は入力先へ戻り、英数・かなを切り替えてください。除外したアプリでは選択の記録と個人候補の優先表示を止めます。プライベート・パスワード入力と、入力先を判別できない場合も記録しません。プライベート入力を識別できないアプリは除外してください。

「学習記録」で選択回数と訂正内容を確認し、Kanade 側の記録を削除できます。記録は50件ずつ表示します。件数と「前へ」「次へ」は、一覧をスクロールしても画面上部で操作できます。

起動診断のログは `~/Library/Logs/Kanade/settings-imk.log` と `settings-ui.log` に保存します。時刻・プロセスIDと、メニュー操作の配送・起動・再表示・設定取得の状態、ウインドウが見えているかどうかだけを記録し、入力文字やキーは記録しません。各ファイルは64 KiBに達すると古い記録を消去します。

接続切断・変換ワーカーの再起動・エンジンの終了理由は、データディレクトリの `logs/engine-events.log` に保存します。標準のmacOSインストールでは `~/Library/Application Support/kanade-ime/logs/engine-events.log`、Windowsでは `%LOCALAPPDATA%\kanade-ime\logs\engine-events.log` です。入力側の復旧とライフサイクルは `~/Library/Logs/Kanade/input-events.log` に記録します。いずれも時刻・プロセスID・あらかじめ決めた出来事の名前・同じ出来事が続いた回数だけで、入力文字、キー、アプリや文書の名前は記録しません。出来事によっては、終了コード、再起動の回数、panic が起きたスレッドの種類とソース上の位置が付きます。panic のメッセージは入力中の文字を含むことがあるので記録しません。64 KiBで古い記録を消去します。

Windowsでエンジンが止まったときは、このファイルの次の記録を見ます。各行の先頭は UNIX 時刻（秒）と、書いたプロセスのIDです。

| 記録 | 意味 |
|---|---|
| `watch-started` | 監視が始まった。サインイン時のほか、入力 DLL が監視を起動したときにも記録する |
| `engine-started` | エンジンが入力を受け付け始めた |
| `engine-exited code=…` | エンジンのプロセスが終了した。`code=1` は直前の `fatal-` で始まる記録が理由、`code=2` は別のエンジンが動作中、`code=101` は panic による終了。それ以外の値（`0xc000013a` など）は外部から終了させられた |
| `engine-restarted count=…` | 監視がエンジンを起動し直した。回数は監視が起動するたびに数え直し、最初の再起動を1回とする |
| `panicked thread=… at=…` | panic が起きたスレッドの種類と、ソースのファイル名・行番号 |
| `recovered-from-panic` | panic の後、全セッションを破棄し変換ワーカーを入れ替えて続行した |
| `connection-refused-at-capacity` | 同時に接続できるアプリの上限（32）に達し、新しい接続を断った |
| `connection-rejected` | 接続直後に相手が終了した、または同じユーザー・セッションのプロセスではなかった |
| `listener-failed`・`fatal-listener-lost` | 接続を受け付けるパイプを用意できなかった。続いた場合はエンジンを終了し、監視が起動し直す |
| `sandboxed-hosts-unreachable` | ストアアプリのように制限された環境で動くアプリに、接続先がエンジンであることを確かめる許可を出せなかった。そのアプリでは変換できない。ほかのアプリには影響しない |
| `settings-unreadable` | 設定ファイルを読めなかった。切り替え式の機能をすべて止めて変換を続け、ファイルは書き換えない |
| `learning-store-unreadable` | 学習の記録を読めなかった。Kanade の学習を止めて変換を続け、ファイルは書き換えない |

前回の `engine-started` から次の `engine-started` までに `engine-exited` がなければ、前のエンジンの終了コードはログから確認できません。途中に `watch-started` があっても同様です。作業中に入力 DLL が監視を起動した場合も、サインイン時と同じ `watch-started` が記録されます。この記録だけでは、前のエンジンに監視がなかったのか、監視も一緒に終了したのかは区別できません。

署名済みバンドルへ接続する場合は、同梱の CLI を使ってください。

```bash
KANADE_UI="$HOME/Library/Input Methods/Kanade.app/Contents/Helpers/Settings.app/Contents/MacOS/kanade-ui"
"$KANADE_UI" settings
"$KANADE_UI" settings set settings.json
"$KANADE_UI" learning list
"$KANADE_UI" learning delete 1
"$KANADE_UI" learning block こうせい
"$KANADE_UI" learning clear
"$KANADE_UI" learning clear-mozc-conversion
"$KANADE_UI" learning clear-mozc-prediction
"$KANADE_UI" dictionary list
"$KANADE_UI" dictionary list 50
```

`learning clear` は Kanade の訂正記録を消去します。Mozc の変換学習と予測学習は、対応する `clear-mozc-*` で個別に消去できます。消去は取り消せません。Mozc の消去は、未確定入力や文書への反映待ちがある間は拒否します。消去対象をGUIで選んでから「消去する」で実行します。「キャンセル」なら学習は変わりません。

`settings set` は `settings` が出力した JSON を読み込みます。学習しないアプリは `learning_excluded_apps` に指定します。空の配列 `[]` は全アプリを対象にします。旧設定ファイルの `learning_apps` は読み込み時に廃止し、除外一覧には引き継ぎません。学習自体のオン・オフと、ほかの設定は維持します。プライベート入力を識別できないアプリは除外してください。ライブ変換と自動の執筆支援は未提供で、有効化する設定は受け付けません。

データディレクトリの設定ファイル（`kanade/settings.toml`）か学習の記録（`kanade/learning.json`）を読めないときも、エンジンは起動して変換を続けます。途中で切れたファイルや、新しい版が書いた項目を含むファイルが当たります。読めなかったファイルは書き換えず、設定画面の上部にそのことを表示します。

- 設定を読めないときは、学習・Tsumugi・プロジェクト辞書・日付の計算・絵文字辞書・句読点での確定をすべて止め、候補の数と文字の大きさは既定値にします。Mozc も学習しません。この間は設定を保存できません。ファイルを直すか削除してから設定画面の「更新」を押すと、読み直します。
- 学習の記録を読めないときは、Kanade の学習だけを止めます。直すか削除してから、エンジンが起動し直す（サインインし直すなど）と読み直します。

`dictionary list` はMozcのユーザー辞書を50件ずつ表示します。次のページはオフセットを指定してください。参照できるファイルの上限は8MiB・100辞書・10万語です。登録・編集・削除と、訂正記録からの明示的な登録は[辞書の管理](dictionary-management.md)を参照してください。自動の昇格は未提供です。

ユーザー辞書は、学習を許可したアプリの通常入力で使えます。除外したアプリとプライベート入力では、Mozcのシークレットモードによりユーザー辞書の候補も無効になります。

候補を選んで `Ctrl＋Delete` を押すと、その語のMozc学習履歴を削除します。macOSでは通常 `Control＋fn＋Delete` です。固定版Mozcの制約により、対象は元の第1候補が選ばれている場合に限ります。プライベート入力では削除しません。学習語・プロジェクト語などの合成候補と、文字種やほかの順位の候補も対象外です。削除できると未確定の読みに戻ります。辞書の語自体は残るので、再変換後も候補には出ることがあります。Kanadeの訂正記録を消す場合は、別途 `learning delete` を使ってください。

「いっしゅうかんご」「いっしゅうかんまえ」「こんげつまつ」「らいげつまつ」「せんげつまつ」を変換すると、現地日付から計算したISO形式と年月日の候補を追加します。「計算日付」の設定、または `calculated_dates` で切り替えられます。「きょう」「あした」などはMozcの既存候補を使います。日付の計算では営業日や祝日を考慮しません。

計算候補を表示した後で日付が変わっても、その表示値を確定します。次の入力から新しい日付を使います。日付の取得は起動時と1分ごとに行い、日付の境界や情報の期限を過ぎた場合は、再取得まで新しい計算候補を出しません。計算候補の確定は訂正学習や予測履歴へ追加しません。

## ローカルAIによる候補の並べ替え

「入力・変換」の「AI変換」で、Tsumugi のライセンスと端末内処理の内容を確認できます。「同意して使う」を押すと、同梱モデルを取り込み、検証が通り次第 AI変換をオンにします。同梱モデルがない場合は、配布元から入手した GGUF ファイルを選んでください。

準備はバックグラウンドで進みます。設定を閉じても処理は続き、開き直すと進行状況や保存済みの同意を確認できます。モデルの取り込み後にPCを再起動した場合も、必要な検証は自動で再開し、完了するとAI変換を使えます。AI変換をオフにしても、同じモデルを再びオンにするときは保存済みの同意を使えます。

Kanade を更新すると、AI変換がオンの場合はモデルを自動で再検証します。AI変換がオフの場合は「再検証して使う」から再開できます。同梱モデルや利用条件が変わった場合は、新しい内容を確認して同意してください。検証の内容は[ローカルAIの仕様](llm.md)を参照してください。

並べ替えを有効にしているのにモデルを使えず、設定での操作が要るときは、並べ替えの対象になる変換で、候補欄の下部に「AI は設定が必要・通常候補」と出ます。同梱モデルや利用条件が替わったとき、検証に通らなかったとき、モデルの処理が止まったときです。「入力・変換」の「AI変換」で理由と必要な操作が分かります。変換は通常候補のまま続けられます。取り込みや検証が進んでいる間は、この表示は出ません。

学習が有効で、学習の除外一覧に含まれないアプリの通常入力だけが対象です。カーソル直前の最大40文字・読み・候補を端末内の別プロセスで処理します。入力内容は外部へ送信せず、モデル処理用のログやファイルにも保存しません。

確定済みの文章に続けて1〜5文節を変換すると、Tsumugi は文節を1か所だけ置き換えた表記を含め、最大9通りの全文候補を比べます。差が大きい場合に第一候補を更新します。人名・地名の漢字をまとめてかなにする候補や、外来語の中黒を落とす候補は手動で選べます。手動で選んだ表記や、Kanade の学習履歴が優先した表記は保持します。空の入力欄から2〜4文節をまとめて変換したときは、文の前半を手掛かりに、「乗ります」「載ります」のように漢字一字と送り仮名でできた末尾の語の表記を選びます。第一候補を更新した場合は未確定文字列にも反映します。Enterで画面に出ている表記を確定できます。候補を手動で動かすと採点を打ち切ります。

CLIからも導入できます。`models status` で配布元・ライセンス・利用条件を確認してから実行してください。

```bash
"$KANADE_UI" models status
"$KANADE_UI" models import "${KANADE_UI%/MacOS/*}/Resources/models/tsumugi.gguf" --accept-license --accept-local-processing
"$KANADE_UI" models status
"$KANADE_UI" models qualify
"$KANADE_UI" models remove
```

取り込みと再検証はバックグラウンドで進みます。`models status` で完了を確認してください。モデルを削除すると並べ替えを無効にし、取り込んだコピーと同意・検証の記録を消します。取り込み元のファイルは保持します。

## 絵文字辞書

6系統を統合した絵文字辞書を同梱しています。収録元はemojibaseの日本語と英語、emoji-jaとemojilibです。これらにGitHub短縮名とCLDR日本語短縮名を加えています。3,963種類の絵文字を、20,690件の読み・キーワードから検索します。「いいね」「赤いハート」「ロケット」などの読みや、`:thumbsup:` などの短縮名を収録しています。

入力中に外部サイトへ接続しません。読みと変換中の表記を完全一致で検索し、通常候補に続けて最大32件を追加します。入力全体が一致した場合は全体を、文節だけが一致した場合はその文節を置き換えます。結合文字や肌色、旗、絵文字表示の指定は維持します。肌色の候補は肌色を含むキーワードから検索できます。

絵文字の追加候補は「絵文字辞書」の設定または `emoji_dictionary` で切り替えます。Mozcの組み込み候補も引き続き利用できます。追加した絵文字の確定は訂正学習や予測履歴へ登録しません。

取得元の版・ハッシュは [locks/emoji.lock.json](../locks/emoji.lock.json)、生成結果の件数・ハッシュは [manifest.json](../crates/kanade-emoji/data/manifest.json) にあります。更新は明示的に実行します。

```bash
mise run emoji-data
# 取得済みのソース・辞書から生成結果を照合する場合
make emoji-data EMOJI_FLAGS="--offline --check"
```

通常のビルドにはデータの再取得や辞書からの読み生成は不要です。各データのMIT・Unicodeライセンスと、読み生成に使うIPAdicの告知を同梱しています。表示できる絵文字はOSのフォントにも依存します。

## プロジェクト辞書

プロジェクト辞書は CLI で管理します。`KANADE_DATA_DIR` を指定してから、フォルダと対象アプリを登録してください。指定外のフォルダを自動で走査しません。

```bash
mise exec -- cargo run -p kanade-indexer -- approve sample ./sample-project com.example.Editor
mise exec -- cargo run -p kanade-indexer -- list
mise exec -- cargo run -p kanade-indexer -- reading sample CacheRequest キャッシュヨウキュウ
mise exec -- cargo run -p kanade-indexer -- index sample
# フォルダの変更に追従する場合。Ctrl+C で終了します
mise exec -- cargo run -p kanade-indexer -- watch sample
# 別のターミナルで承認を解除すると、監視も終了します
mise exec -- cargo run -p kanade-indexer -- remove sample
```

CLIでの解析には `scan_symbols` / `split_identifier` API を備えた astro-sight が必要です。miseは、このAPIを含む公開済みコミット [`429f894`](https://github.com/owayo/astro-sight/commit/429f894188842b0ba183db766793d4aafca19e12) を固定し、`make setup` でソースからビルドして導入します。既存の実行ファイルを使う場合は `KANADE_ASTRO_SIGHT` で指定できます。パッチの適用は不要です。

開発用語とよく使う複数形663件の初期読みを同梱しています。`CacheRequest` などの複合語や `Utf8` などの英数字名にも対応します。未登録の英字は綴り読みを使います。

プロジェクト辞書を設定JSONの `project_dictionary` で有効にすると、登録したアプリにだけ候補を出します。読み全体が一致する識別子は、Mozcが複数文節に分けても一つの候補として選べます。識別子ごとの読みは `reading` で指定でき、同梱の読みより優先されます。変更後は再索引してください。監視中なら自動で反映されます。

承認を解除すると、生成した辞書を削除し、元のフォルダを保持します。フォルダを置き換えた場合は、承認を解除して登録し直してください。

登録済みプロジェクトの停止・再開、対象アプリの変更、読みの上書き解除もCLIで操作できます。`disable` は監視を停止します。自動反映を有効にしていれば `enable` で再開します。CLIの監視は、改めて `watch` を起動してください。

```bash
mise exec -- cargo run -p kanade-indexer -- disable sample
mise exec -- cargo run -p kanade-indexer -- enable sample
mise exec -- cargo run -p kanade-indexer -- apps sample com.example.Editor com.example.Terminal
mise exec -- cargo run -p kanade-indexer -- clear-reading sample CacheRequest
```

CLIの `watch` は、明示的に起動した間だけ動きます。OSのファイル通知をまとめて再解析し、解析に失敗した場合は直前の索引を残します。フォルダの移動・置き換えや承認解除を検出すると終了します。エンジンは新しい索引と承認の変更を入力処理とは別のスレッドで読み込みます。通知を利用できない環境では、署名済みアプリに同梱したCLIで `reload-projects` を実行してください。

自動反映と手動の作成処理は一つのキューで解析し、手動操作を優先します。複数フォルダでは待ち時間の長いものから処理します。監視中は解析の優先度を下げ、全体走査の後に休止期間を設けます。失敗した更新は間隔を延ばしながら再試行します。ネットワークドライブは通知を保証できないため、監視の対象外です。Windowsの通知機能は現行バックエンドの制約で無効にしており、明示的な索引更新と再読込を使います。

監視からの再解析には全体走査を使います。astro-sight拡張の差分APIでは除外ルールに差があるためです（[報告 #395](https://github.com/owayo/astro-sight/issues/395)）。明示的な `index sample src/main.rs` は差分APIを使用するので、除外対象のファイルを渡さないでください。

`make project-contract` はMozcワーカーをビルドし、承認・読み・差分更新に加え、実際のファイル通知による追加・削除・名前変更・除外ルール変更・解析失敗・承認解除を試験できます。既定ではmiseで固定した解析器を使います。`KANADE_ASTRO_SIGHT` で別の実行ファイルを指定することもできます。

## 学習・評価用の変換候補

`kanade-eval candidates` は、かなの読みと文脈を受け取り、各文節の変換候補をJSON Linesで返します。Tsumugiの学習・評価データを作る際に使えます。先に `make worker` で固定したMozcワーカーをビルドしてください。

```bash
printf '%s\n' '{"id":"sample","reading":"にほんごをにゅうりょくする","preceding":""}' |
  cargo run --locked -p kanade-eval -- candidates --limit 50 --max-reading 96
```

先頭行はワーカーと辞書の識別情報です。その後は入力1行につき応答1行を返し、成功時は各文節の読み、候補、候補数、第一候補の全文を含みます。失敗した行も、固定のエラー分類を返します。要求は1行64KiBまでです。読み・文脈を診断出力へ書きません。

空の一時プロファイルで学習を無効にし、行ごとに独立したセッションで処理します。候補を取る前の入力補完は省きます。`--suggest` で補完を使った比較もできます。`--deadline-ms` は評価用ワーカーの待ち時間を指定し、通常のIME入力の期限には影響しません。ヘッダーのKanadeコミットは、未変更のGitチェックアウトからビルドした場合に記録します。

## 文章の確認

明示的に渡した確定済みの文章を、noslop の読みやすさルールで確認できます。変換候補と混ぜず、自動では書き換えません。文章は保存しません。

```bash
cargo run -p kanade-ui --features native -- assist < draft.txt
cargo run -p kanade-ui -- assist-json < draft.txt
```

既定は文単位の検査です。全文を渡すときだけ `--whole-document` を指定すると、文書単位の検査も使います。出力の位置は UTF-16 単位です。
